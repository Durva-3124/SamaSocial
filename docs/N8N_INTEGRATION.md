# n8n Integration Reference

This document describes the backend interfaces and behavior relevant to building n8n workflows. The API is REST/JSON under `/api`, except endpoints marked SSE or file download. No GraphQL API is defined.

## 1. API Endpoints

### Base URL and headers

- Development backend: `http://127.0.0.1:8000` (also commonly `http://localhost:8000`). The frontend Vite proxy forwards `/api` to `http://127.0.0.1:8000`.
- No deployed staging or production base URL is defined in the repository. Configure the actual backend origin in n8n.
- No application API endpoint requires authentication headers.
- JSON requests: `Content-Type: application/json`; SSE requests should send `Accept: text/event-stream`; file uploads use `multipart/form-data`.
- FastAPI's autogenerated `/openapi.json`, `/docs`, and `/redoc` routes are also enabled by default.

### Endpoint inventory

| Method and path | Request | Success response |
|---|---|---|
| `GET /api/health` | No body | `200 {"status":"ok"}` |
| `POST /api/sessions` | No body | `201 {"session_id":"<id>"}` |
| `POST /api/sessions/{sid}/sources/file` | Multipart field `file`; PDF or PPTX | `202 {"source_id":"<id>","status":"processing"}` |
| `POST /api/sessions/{sid}/sources/url` | `{"url":"https://..."}` | `202 {"source_id":"<id>","status":"processing"}` |
| `GET /api/sessions/{sid}/sources` | No body | `200 {"sources":[...]}` |
| `DELETE /api/sessions/{sid}/sources/{source_id}` | No body | `204`, empty body |
| `POST /api/sessions/{sid}/chat` | `{"message":"...","mode":"normal"}`; mode can be `simple` | SSE events (below) |
| `POST /api/sessions/{sid}/quiz` | `{"num_questions":5,"source_ids":null}` | `200 {"questions":[...]}` |
| `POST /api/courses` | No body | `201 {"course_id":"<id>"}` |
| `GET /api/courses/{cid}` | No body | `200` course state (below) |
| `POST /api/courses/{cid}/chat` | `{"message":"..."}` | SSE events (below) |
| `PATCH /api/courses/{cid}/plan` | `{"path":"/modules/0/title","value":"New title"}` | `200 {"plan":{...},"plan_version":1}` |
| `POST /api/courses/{cid}/resources/refresh` | `{"lesson_id":null}` or `{"lesson_id":"m1-l2"}` | SSE events (below) |
| `GET /api/courses/{cid}/export` | No body | JSON file attachment |
| `POST /api/courses/{cid}/syllabus` | Multipart `file` (PDF); optional query `?replace=true` | SSE events (below) |

`sid`, `cid`, and `source_id` are IDs returned by the corresponding creation/upload endpoints. IDs are generated as UUID hex strings.

### Source responses and processing

`GET /api/sessions/{sid}/sources` returns records like:

```json
{
  "sources": [
    {
      "id": "source-id",
      "type": "pdf",
      "name": "lesson.pdf",
      "status": "processing",
      "error": null,
      "chunk_count": 0,
      "summary": null,
      "topics": []
    }
  ]
}
```

`type` is `pdf`, `pptx`, `youtube`, or `web`; `status` is `processing`, `ready`, or `failed`. Upload and URL ingestion are asynchronous. A `202` only confirms that processing started. Poll the sources endpoint until `ready` or `failed`; the README describes a 2-second polling interval. Failures after acceptance are stored in `error` on the source record.

Limits: 25 MB per uploaded file by default; at most 8 sources per session. File endpoints accept `.pdf` and `.pptx`; syllabus accepts PDF only. Unsupported files return `415`, oversized files `413`, duplicate sources `409`, and a missing session `404`. A URL must be public HTTP(S); local/private targets are rejected. A non-YouTube URL is ingested as a webpage.

### Chat SSE

Chat endpoints return `Content-Type: text/event-stream`, with each event serialized as `event: <name>\ndata: <JSON>\n\n`.

Learning assistant events:

- `token`: `{"text":"partial answer"}`
- `citations`: `{"items":[{"label":"S1","source_id":"...","source_name":"...","source_type":"pdf","locator":{},"locator_text":"page 2","snippet":"..."}]}`
- `done`: `{"declined":false,"used_source_ids":["..."]}`
- `error`: `{"code":"...","message":"..."}`

Course chat events:

- `token`: `{"text":"partial answer"}`
- `intake_state`: `{"intake":{...},"missing":["topic"]}`
- `plan_update`: `{"plan":{...},"plan_version":1,"changed_ids":["m1"]}`
- `resources_unavailable`: `{"reason":"..."}`
- `done`: `{}`
- `error`: `{"code":"...","message":"..."}`

Resource refresh emits `plan_update` then `done`, or `resources_unavailable` then `done`. Syllabus upload can emit `intake_state`, `plan_update`, `token`, and `done`; it emits `PLAN_EXISTS` as an SSE `error` event if a plan already exists and `replace=true` was not supplied.

For n8n, treat SSE responses differently from normal JSON responses: use an HTTP/stream handling path that preserves and parses event frames. Some failures are SSE `error` events rather than non-2xx JSON responses.

### Quiz and course response examples

Quiz request and response shape:

```json
{"num_questions":5,"source_ids":null}
```

```json
{
  "questions": [
    {
      "question": "Question text",
      "options": ["A", "B", "C", "D"],
      "answer_index": 0,
      "explanation": "Explanation",
      "source_id": "source-id",
      "locator_text": "page 2"
    }
  ]
}
```

`source_ids` may be `null` or a list of IDs. If no chunks exist for the chosen sources, the endpoint returns `422` (`NO_SOURCES`). `num_questions` defaults to 5; the route model does not declare a numeric range.

Course state response shape:

```json
{
  "intake": {
    "topic": null,
    "level": null,
    "duration_weeks": null,
    "sessions_per_week": null,
    "age_group": null,
    "prior_knowledge": null,
    "goals": [],
    "prerequisites": [],
    "extra": {}
  },
  "missing": ["topic", "level"],
  "plan": null,
  "plan_version": 0,
  "messages": [{"role": "assistant", "content": "..."}]
}
```

`PATCH /courses/{cid}/plan` uses an RFC 6901 JSON Pointer in `path`. It only permits selected paths and validates the modified plan; invalid paths or values return `422`. A course with no plan returns `400` for plan patch/export. Export returns the course plan JSON with a `Content-Disposition` filename.

### Error responses

Structured application errors use:

```json
{"error":{"code":"ERROR_CODE","message":"Human-readable message"}}
```

Common statuses include `404` for missing IDs, `400` for request/state conflicts, `413` for file size, `415` for unsupported file type, and `422` for invalid data or unsafe/unavailable source input. SSE operations can report errors in an `error` event instead.

## 2. Authentication

There is no API authentication or authorization. Session/course IDs are unprotected identifiers; anyone who knows an ID can use the corresponding endpoints. They should not be treated as secure credentials.

The backend uses a server-side LLM provider key. The LLM client sends `Authorization: Bearer <LLM_API_KEY>` only on its outbound provider requests; n8n does not send that key to this app. Auth-related environment variables are `LLM_API_KEY`, and optional third-party keys `YOUTUBE_API_KEY` and `TAVILY_API_KEY`.

## 3. Triggers and Events

- Incoming webhooks: none.
- Outgoing webhooks/callbacks: none.
- Scheduled jobs or cron tasks: none found.
- Database triggers, queue events, and pub/sub: none found.
- Source ingestion: started by a request and continued as an in-process background task; completion is observed by polling the sources endpoint.
- Course resource refresh, chat, and syllabus restructuring: started by API requests; progress/results are streamed to that request using SSE.

An n8n workflow should use its own trigger (for example, webhook, schedule, or manual trigger) to call this API. There is no callback URL setting in this project.

## 4. Data Models

Models are defined primarily in `backend/app/models/course.py`, `session.py`, `chunk.py`, and `llm.py`.

- **Message:** `role` is `user` or `assistant`; `content` is a string.
- **Source:** ID, type (`pdf`, `pptx`, `youtube`, `web`), name, status (`processing`, `ready`, `failed`), optional error/summary, chunk count, topics, and internal warnings. The source-list endpoint omits warnings.
- **Locator:** Optional `page`, `slide`, `start_seconds`, and `heading`; used in citation responses.
- **IntakeData:** Optional topic, level, duration weeks, sessions per week, age group, and prior knowledge; goals/prerequisites are string arrays; `extra` is an object. Plan generation requires topic, level, duration weeks, sessions per week, age group, and prior knowledge.
- **Course:** Required `title`; defaults include empty description/goals/modules, level `beginner`, and `total_weeks` 4. Optional `audience` and `duration`.
- **Audience:** Required `age_group`, difficulty `level`, and `prior_knowledge`.
- **Duration:** `weeks` 1–52, `sessions_per_week` 1–7, `session_minutes` 15–240.
- **Module:** Required `id` and `title`; difficulty defaults to `beginner`; prerequisites and lessons default to empty arrays.
- **Lesson:** Required `id` and `title`; `duration_minutes` defaults to 30; difficulty defaults to `beginner`; objectives, topics, and resources default to empty arrays.
- **Resource:** Required `title` and `url`; type is `video`, `article`, `exercise`, or `other` (default); `validated` defaults to false.

Difficulty values are `beginner`, `intermediate`, or `advanced`. Course validation limits a plan to 8 modules and 60 lessons total. The full course schema is in `docs/course.schema.json`. Patchable paths and additional value checks are defined in `backend/app/services/plan_ops.py`.

## 5. Environment and Configuration

Settings are read from `backend/.env`; the checked-in example is `backend/.env.example`.

| Variable | Default | Purpose |
|---|---|---|
| `LLM_BASE_URL` | `https://api.groq.com/openai/v1` | OpenAI-compatible provider URL |
| `LLM_API_KEY` | Empty | Provider key; required for LLM calls |
| `LLM_MODEL` | Empty | Provider model name; required for LLM calls |
| `EMBEDDING_MODEL` | `sentence-transformers/all-MiniLM-L6-v2` | Local embedding model |
| `FRONTEND_ORIGIN` | `http://localhost:5173` | CORS allowed origin |
| `MAX_UPLOAD_MB` | `25` | Maximum upload size |
| `SESSION_TTL_MINUTES` | `120` | Inactivity TTL for sessions and courses |
| `RETRIEVAL_TOP_K` | `6` | Retrieval chunk limit |
| `RETRIEVAL_MIN_SCORE` | `0.30` | Minimum retrieval similarity |
| `YOUTUBE_API_KEY` | Unset | Optional YouTube Data API key for resource enrichment |
| `YOUTUBE_PROXY` | Unset | Optional proxy for YouTube transcript retrieval |
| `TAVILY_API_KEY` | Unset | Optional Tavily key for resource enrichment |

No application-level API rate limiter is defined. LLM requests have a 30-second timeout and retry a `429` once when the provider's `Retry-After` is at most 10 seconds. URL ingestion rejects unsafe/private targets; webpage retrieval allows up to 5 MB, a 15-second fetch timeout, and 3 redirects. Stores are in-memory, are lost on server restart, and are not shared between multiple workers; the README recommends a single Uvicorn worker.

## 6. Existing Integrations

- **OpenAI-compatible LLM (Groq by default):** Used for assistant chat, summaries, quizzes, intake, and course planning. Configured by `LLM_BASE_URL`, `LLM_API_KEY`, and `LLM_MODEL`; calls are triggered by relevant API requests.
- **Sentence Transformers:** Local embeddings for ingestion and retrieval, configured with `EMBEDDING_MODEL`; no embedding API key is used.
- **YouTube transcript retrieval:** Triggered by submitting a YouTube source URL; uses `youtube-transcript-api` with a `yt-dlp` fallback. `YOUTUBE_PROXY` is optional.
- **YouTube Data API v3:** Used during explicit course resource refresh when `YOUTUBE_API_KEY` is configured.
- **Tavily Search API:** Resource-search fallback during course resource refresh when `TAVILY_API_KEY` is configured. Candidate URLs are validated before use.
- **Web fetching:** Triggered by submitting a non-YouTube URL as a source; fetches and extracts public HTTP(S) webpage content.
- **Local document parsing:** PDF and PowerPoint processing uses local libraries; no cloud document service is configured.
- **Not present:** No Slack, email, Google Sheets, database, external queue, or pub/sub integration was found.

## n8n Workflow Notes

1. Create and retain a session/course ID before calling its child endpoints.
2. After source upload, poll source status; a `202` response is not a completion signal.
3. Preserve the IDs for follow-up chat, source deletion, quiz, course state, and export calls.
4. Account for SSE responses on chat, course chat, resource refresh, and syllabus upload.
5. Do not rely on server persistence: current IDs/data expire after inactivity or backend restart.
